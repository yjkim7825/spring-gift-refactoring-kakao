# 쓰이지 않는 코드 정리 점검

작업 목록을 실행 뒤에 작성함. 코드를 먼저 지우고, 지운 뒤에 근거와 확인 결과를 모아 적었다. 작업 내용은 [1단계 기록](README.md)에 있다.

| D1  | 주문 처리에 연결만 해 두고 쓰지 않는 위시 | 없음      | 안건 #4, 모순 M-2의 근거로 쓰인다                       | 기획 판단 필요 | 안건 #4 결정 전까지 보류. 지웠다가 되돌렸다 |

D1, D2는 3단계에서 주문 규칙을 옮길 때도 위시 연결과 설명을 그대로 옮긴다. 안건 #4가 정해지면 그 결정에 따라 지우거나 위시 정리를 만든다.

## 항목별 근거

### D1. 주문 처리의 위시 연결

- 주변 주석: 바로 아래 주문 처리 설명에 "위시 정리" 단계가 있다. 위시 연결과 이 설명은 같은 의도, 즉 주문 뒤 위시를 정리하려던 흔적으로 보인다.
- 추가한 사람과 이유: 프로젝트를 처음 만든 커밋에서 다른 코드와 함께 들어왔다. 따로 남긴 설명은 없다.
- 안건과의 관계: 안건 #4(주문하면 위시에서 빠지는가)와 모순 M-2의 근거로 문서에 적혀 있다. 지우면 "정리하려고 준비해 둔 흔적"이 코드에서 사라진다.
- 판단: 동작은 바뀌지 않는다. 다만 안건 #4가 정해지기 전에 의도의 흔적을 지우는 것이라 기획 판단이 필요하다.
- 결과: 안건 #4 결정 전까지 보류. 코드를 원래대로 돌렸다.

### D2. "위시 정리" 단계 설명

- 주변 주석: 주문 처리 순서 7단계 중 6번째로 적혀 있었다. 할 일 표시(TODO)는 없다.
- 추가한 사람과 이유: D1과 같은 커밋이다.
- 안건과의 관계: [모순 M-2](../../contradictions.md#m-2-주문하면-위시에서-빠지는가)는 "설명에는 위시 정리가 있다"와 "실제로는 하지 않는다"가 서로 다르다는 내용이다. 이 설명을 지우면 모순의 한쪽이 없어진다. "위시를 정리하지 않는다" 쪽으로 모순을 정리한 것과 같다.
- 판단: 동작은 바뀌지 않는다. 그러나 모순을 어느 쪽으로 정리할지는 기획 판단이라, 안건 #4보다 먼저 지워서는 안 된다.
- 결과: 안건 #4 결정 전까지 보류. 코드를 원래대로 돌렸다.

### D3. 주문에서 주문한 회원을 꺼내는 코드

- 주변 주석: 회원을 번호로만 들고 있다는 짧은 주석뿐이다. 할 일 표시는 없다.
- 추가한 사람과 이유: 프로젝트를 처음 만든 커밋이다.
- 안건과의 관계: 없다. 내 주문 내역은 이 코드가 아니라 저장된 회원 번호로 찾는다.
- 관리자 화면: 쓰는 곳이 없다.
- 판단: 문제없음. 지우고 커밋했다.

### D4. 상품에서 옵션 목록을 꺼내는 코드

- 주변 주석: 없다. 할 일 표시도 없다.
- 추가한 사람과 이유: 프로젝트를 처음 만든 커밋이다.
- 안건과의 관계: 없다. 상품을 지우면 옵션도 함께 지우는 설정은 그대로 남겼다. [안건 #3](../../agenda.md#고칠지-정할-동작)과 모순 M-1(상품에 옵션이 꼭 있어야 하는가)은 이 코드를 근거로 쓰지 않는다.
- 관리자 화면: 쓰는 곳이 없다.
- 판단: 문제없음. 지우고 커밋했다.

D1, D2를 지웠을 때는 [모순 M-2](../../contradictions.md#m-2-주문하면-위시에서-빠지는가), [주문 흐름 분석](../../order-flow.md#주문-처리-순서)의 "코드의 주석에는 위시 정리가 있다"는 문장, 안건 #4 근거, O-9 근거가 코드와 맞지 않았다. 1단계에서 안건 #4 근거와 O-9 근거를 고쳤지만, M-2와 주문 흐름 분석 본문은 놓쳤다.

D1, D2를 되돌리면서 고쳤던 두 근거도 원래대로 돌렸다. 지금은 네 곳 모두 코드와 맞다. D3, D4를 근거로 쓴 문서는 없다.
