# 안건

리팩터링 전에 기획에서 정해야 할 것을 모았다. 현재 동작은 [사용자 스토리](user-stories.md)에, 주문 분석은 [주문 흐름 분석](order-flow.md)에, 모순은 [모순 목록](contradictions.md)에 있다.

## 서비스 방향

### 선물 주문인가, 내 구매인가

서비스 이름과 알림 문구는 "선물하기"인데, 주문 구조는 "내가 사서 내가 받는" 구매다([M-4](contradictions.md#m-4-주문은-선물인가)).

- 주문에는 받는 사람이 없다. 주문한 회원만 기록한다.
- 메시지는 선물 받는 사람에게 쓰는 말처럼 보이지만("생일 축하해!"), 실제로는 주문한 사람에게 돌아간다.
- 알림은 카카오톡 "나에게 보내기"로 보낸다.

어느 쪽으로 정하느냐에 따라 주문 도메인의 모양이 달라진다.

- 선물 주문으로 정하면: 받는 사람, 받는 사람에게 보내는 알림, 선물 수락이나 거절 같은 상태가 필요하다.
- 내 구매로 정하면: 알림 문구와 메시지의 쓰임을 고쳐야 한다.

아래 안건 중 #11, #19가 이 결정을 따른다.

## 만들지 정할 기능

이런 서비스라면 흔히 기대하지만 지금은 없는 기능이다. 각각 만들지 정해야 한다.

| 영역 | 없는 기능                                                                          |
| ---- | ---------------------------------------------------------------------------------- |
| 회원 | 회원 스스로 포인트 충전, 비밀번호 변경과 찾기, 회원 탈퇴                           |
| 상품 | 카테고리별 상품 보기, 상품 검색                                                    |
| 주문 | 선물 받을 사람 지정, 여러 상품 한 번에 주문, 주문 하나 따로 보기, 주문 취소와 환불 |
| 운영 | 옵션과 카테고리 관리 화면, 옵션 수정, 재고 보충, 포인트 회수, 관리자 로그인        |

## 개발자 참고

본문을 코드와 연결하기 위한 정보다. 비개발자는 읽지 않아도 된다.

### "고칠지 정할 동작"의 근거

#13~19의 근거는 [주문 흐름 분석의 문제별 근거](order-flow.md#문제별-근거)에 O 번호로 있다.

| #   | 근거                                                                                                                                                                                                                                             |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | `AdminProductController`, `AdminMemberController`, `CategoryController`, `ProductController`, `OptionController`의 변경 API에 인증 확인이 없다                                                                                                   |
| 2   | `Member.point`의 기본값이 0이다. 포인트를 늘리는 경로는 `AdminMemberController.chargePoint`뿐이다                                                                                                                                                |
| 3   | `ProductController.createProduct`와 `AdminProductController.create`는 옵션을 만들지 않는다. `templates/`에는 `member/`, `product/`만 있고 옵션과 카테고리 화면이 없다. `OptionController` 주석에는 "상품에는 항상 옵션 1개 이상"이라고 적혀 있다 |
| 4   | `OrderController.createOrder` 주석에는 "6. cleanup wish"가 있지만, `wishRepository`를 주입만 하고 쓰지 않는다                                                                                                                                    |
| 5   | `OrderController.createOrder`에 `@Transactional`이 없다. `optionRepository.save`로 재고 차감을 먼저 커밋한 뒤 `member.deductPoint`에서 예외가 날 수 있다                                                                                         |
| 6   | `Option.subtractQuantity`, `Member.deductPoint`가 `IllegalArgumentException`을 던지는데, `OrderController`에 `@ExceptionHandler`가 없어 `500`이 예상된다                                                                                         |
| 7   | `@RequestHeader("Authorization")`이 필수라서 헤더가 없으면 `401` 대신 `400 MissingRequestHeaderException`이 예상된다                                                                                                                             |
| 8   | `ProductNameValidator.validate(name, allowKakao)`를 관리자 화면은 `true`, API는 `false`로 호출한다                                                                                                                                               |
| 9   | `Member.password`가 평문이고, `templates/member/edit.html`에서 `th:value="${member.password}"`로 채운다                                                                                                                                          |
| 10  | `V1__Initialize_project_tables.sql`에서 `wish`, `orders`, `product`의 FK에 `ON DELETE` 옵션이 없다. 관리자 화면의 삭제는 예외 처리 없이 `deleteById`를 호출한다                                                                                  |
| 11  | `KakaoMessageClient`가 `/v2/api/talk/memo/default/send`("나에게 보내기")를 쓴다                                                                                                                                                                  |
| 12  | `OrderResponse`의 필드가 `id`, `optionId`, `quantity`, `orderDateTime`, `message`뿐이다. `GET /api/orders/{id}`가 없다                                                                                                                           |
