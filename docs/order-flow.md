# 주문 흐름 분석

주문은 이 서비스의 핵심 도메인이다. 회원의 포인트, 옵션의 재고, 상품의 가격, 카카오 알림이 모두 주문 한 번에 함께 움직인다.
용어의 뜻은 [용어 사전](glossary.md)에, 주문 기능의 사용자 스토리는 [사용자 스토리](user-stories.md)의 US-10~12에 있다.

## 주문에 관여하는 것

| 대상   | 주문에서 하는 일                                                                       |
| ------ | -------------------------------------------------------------------------------------- |
| 회원   | 주문하는 사람. 포인트로 결제하고, 카카오에 연동되어 있으면 알림을 받는다.              |
| 옵션   | 주문하는 대상. 주문 수량만큼 재고가 줄어든다.                                          |
| 상품   | 옵션이 속한 상품. 상품 가격으로 주문 금액을 계산한다.                                  |
| 주문   | 주문한 결과를 남기는 기록. 옵션, 회원, 수량, 메시지, 주문 일시를 남긴다.               |
| 카카오 | 주문을 마친 뒤 회원에게 알림을 보낸다.                                                 |
| 위시   | 원래는 주문한 상품을 위시에서 지우려던 것으로 보이지만, 지금은 주문에 관여하지 않는다. |

## 주문 처리 순서

회원이 옵션, 수량, 메시지를 보내면 다음 순서로 처리한다. 앞 단계에서 실패하면 뒤 단계는 실행하지 않는다.

1. 입력 확인: 옵션을 골랐는지, 수량이 1개 이상인지 확인한다. 메시지는 비워도 되고 길이 제한이 없다.
2. 로그인 확인: 로그인한 회원인지 확인한다.
3. 옵션 확인: 고른 옵션이 있는지 확인한다.
4. 재고 차감: 남은 재고가 주문 수량 이상인지 확인하고, 재고를 줄여 바로 저장한다.
5. 포인트 차감: 주문 금액(상품 가격 × 수량)을 계산한다. 포인트가 충분한지 확인하고, 포인트를 줄여 바로 저장한다.
6. 주문 기록: 주문을 저장한다. 주문 일시는 이때의 서버 시각이다.
7. 카카오 알림: 회원이 카카오에 연동되어 있으면 알림을 보낸다. 실패해도 주문은 성공으로 처리한다.
8. 결과 응답: 저장한 주문을 돌려준다.

코드의 주석에는 6단계와 7단계 사이에 "위시 정리"가 있지만 실제로는 실행하지 않는다.

## 단계별로 실패하면 무엇이 남는가

4~6단계는 한 묶음으로 처리되지 않는다. 단계마다 따로 저장하기 때문에, 중간에 실패하면 앞 단계에서 바뀐 것이 되돌려지지 않는다.

| 실패 지점             | 재고           | 포인트         | 주문 기록 | 회원이 받는 안내                         |
| --------------------- | -------------- | -------------- | --------- | ---------------------------------------- |
| 로그인하지 않음       | 그대로         | 그대로         | 없음      | 로그인 필요 또는 잘못된 요청 (확인 필요) |
| 옵션이 없음           | 그대로         | 그대로         | 없음      | 찾을 수 없음                             |
| 재고 부족             | 그대로         | 그대로         | 없음      | 이유 없는 서버 오류 (확인 필요)          |
| 포인트 부족           | 줄어든 채 남음 | 그대로         | 없음      | 이유 없는 서버 오류 (확인 필요)          |
| 메시지가 255자를 넘음 | 줄어든 채 남음 | 줄어든 채 남음 | 없음      | 이유 없는 서버 오류 (확인 필요)          |
| 카카오 알림 실패      | 줄어듦         | 줄어듦         | 있음      | 주문 성공 (알림만 오지 않음)             |

포인트 부족이나 메시지 길이 때문에 실패하면 회원은 주문이 안 된 줄 아는데, 재고나 포인트는 이미 빠져 있다. 메시지가 길어서 실패한 경우에는 포인트를 잃고도 주문 기록이 남지 않아 회원이 돌려받을 근거도 없다.

## 발견한 문제

"확정"은 코드만으로 확실한 것, "확인 필요"는 실행해 봐야 확정할 수 있는 것이다. "안건" 칸은 [안건](agenda.md#고칠지-정할-동작)의 "고칠지 정할 동작" 번호다. 주문이 선물인지 내 구매인지는 [안건의 서비스 방향](agenda.md#서비스-방향)에서 다룬다.

## 개발자 참고

본문을 코드와 연결하기 위한 정보다. 비개발자는 읽지 않아도 된다.

### 단계별 코드 위치

모두 `order/OrderController.createOrder` 안에 있다.

| 단계           | 코드                                                                                                 | 실패 시                                               |
| -------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 1. 입력 확인   | `OrderRequest`의 `@NotNull optionId`, `@Min(1) quantity`. `message`는 제약 없음                      | `400`                                                 |
| 2. 로그인 확인 | `@RequestHeader("Authorization")`, `AuthenticationResolver.extractMember`                            | 헤더 없음은 `400` 예상, 토큰 오류나 회원 없음은 `401` |
| 3. 옵션 확인   | `optionRepository.findById`                                                                          | `404`                                                 |
| 4. 재고 차감   | `Option.subtractQuantity`, `optionRepository.save`                                                   | `IllegalArgumentException`, 처리기 없어 `500` 예상    |
| 5. 포인트 차감 | `option.getProduct().getPrice() * request.quantity()`, `Member.deductPoint`, `memberRepository.save` | `IllegalArgumentException`, `500` 예상                |
| 6. 주문 기록   | `orderRepository.save(new Order(...))`, `LocalDateTime.now()`                                        | DB 제약 위반 시 `500` 예상                            |
| 7. 카카오 알림 | `sendKakaoMessageIfPossible`, `KakaoMessageClient.sendToMe`                                          | 모든 예외를 `catch (Exception ignored)`로 무시        |
| 8. 결과 응답   | `201`, `Location: /api/orders/{id}`                                                                  | 해당 주소의 조회 API가 없다                           |

### 문제별 근거

| #    | 근거                                                                                                                                                                                                                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| O-1  | `createOrder`와 그 상위에 `@Transactional`이 없다. `optionRepository.save`, `memberRepository.save`, `orderRepository.save`가 각자의 트랜잭션에서 커밋된다. 프로젝트 전체에 `@Transactional`이 없다                                                                                                |
| O-2  | `OrderController`에 `@ExceptionHandler`가 없고 `@ControllerAdvice`도 없다. `@ExceptionHandler`는 `MemberController`, `ProductController`, `OptionController`에만 있다                                                                                                                              |
| O-3  | `Product.price`와 `quantity`가 `int`이고 곱셈 결과도 `int`다. 1,000,000 × 4,295 = 4,295,000,000은 `int` 범위(2,147,483,647)를 넘어 32,704로 순환한다. 옵션 재고는 99,999,999까지 등록할 수 있어 도달 가능하다. 결과가 음수면 `deductPoint`의 `amount <= 0` 검사에 걸리고, 이미 4단계가 커밋된 뒤다 |
| O-4  | `Option`, `Member`에 `@Version`이나 잠금이 없다. 읽고, 검사하고, 쓰는 사이에 다른 요청이 끼어들 수 있다                                                                                                                                                                                            |
| O-5  | `Order`에 가격이나 금액 필드가 없다. `KakaoMessageClient.buildTemplate`도 알림을 보낼 때의 `product.getPrice()`로 금액을 계산한다                                                                                                                                                                  |
| O-6  | `OrderRequest.message`에 `@Size`가 없고, `orders.message`는 `varchar(255)`다                                                                                                                                                                                                                       |
| O-7  | `buildTemplate`이 메시지를 `String.formatted`로 JSON 문자열 안에 그대로 넣는다. 이스케이프하지 않아 `"`나 줄바꿈이 있으면 JSON이 깨진다                                                                                                                                                            |
| O-8  | `KakaoAuthController.callback`은 `accessToken`만 저장하고 리프레시 토큰은 저장하지 않는다. 만료된 토큰으로 보내면 7단계에서 예외가 나고 무시된다                                                                                                                                                   |
| O-9  | `wishRepository`를 주입만 하고 쓰지 않는다. 위시는 상품 단위, 주문은 옵션 단위라서 정리하려면 `option.getProduct().getId()`로 찾아야 한다                                                                                                                                                          |
| O-10 | `Order`에 수신자 필드가 없다. `KakaoMessageClient`가 `/v2/api/talk/memo/default/send`를 쓴다                                                                                                                                                                                                       |
| O-11 | `OrderResponse`가 `id`, `optionId`, `quantity`, `orderDateTime`, `message`만 담는다. `GET /api/orders/{id}`가 없는데 `201` 응답의 `Location`은 그 주소를 가리킨다                                                                                                                                  |
| O-12 | 템플릿의 `"link": {}`가 비어 있다                                                                                                                                                                                                                                                                  |

### 리팩터링 관점에서 본 구조

- 주문 규칙이 모두 컨트롤러에 있다. `Order` 엔티티는 값을 담기만 하고 규칙이 없다.
- `Order`는 옵션을 엔티티로 참조하지만 회원은 `memberId` 값으로만 들고 있다. `Wish`도 마찬가지로 회원을 값으로 들고 있다.
- 주문에 상태가 없어서 취소, 환불, 배송 같은 이후 단계를 붙일 곳이 없다.
- 카카오 알림을 요청 처리 중에 동기로 보낸다. `RestClient`에 응답 시간 제한을 따로 설정하지 않아서, 카카오가 늦으면 주문 응답도 늦어진다.

### 리팩터링 전에 테스트로 고정할 동작

지금 동작을 그대로 고정할 대상이다. 고칠 동작(O-1~O-12)은 고정하지 말고, 고친 뒤의 기대 동작으로 테스트를 쓴다.

- 정상 주문: 재고와 포인트가 정확히 줄고, 주문이 기록되고, `201`을 돌려준다.
- 로그인하지 않은 주문과 잘못된 토큰: `401`.
- 없는 옵션: `404`.
- 수량 0: `400`.
- 카카오 미연동 회원: 알림을 시도하지 않고 주문은 성공한다.
- 카카오 알림 실패: 주문은 성공한다.
- 주문 내역: 내 주문만, 페이지 단위로 보인다.
